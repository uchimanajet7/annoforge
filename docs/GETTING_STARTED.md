# はじめに

AnnoForgeで画像を編集するだけなら、ブラウザーと画像があれば始められます。AWSの準備や、自分のGitHub Pagesの設定は不要です。

| やりたいこと | 必要な準備 | 手順 |
|---|---|---|
| 画像に注釈を付けて保存する | ブラウザー、画像、インターネット接続 | [ブラウザーで画像を編集する](#ブラウザーで画像を編集する) |
| AIエージェントと同じ画像を編集する | Site tools対応クライアント | [WebMCPでAIエージェントと使う](#webmcpでaiエージェントと使う) |
| 自分のURLでWeb UIを公開する | 自分のGitHubリポジトリ、PagesとActionsを設定・実行する権限 | [GitHub Pagesで自分のサイトを公開する](#github-pagesで自分のサイトを公開する) |
| API経由で画像に注釈を描画する | AWSアカウントと権限、デプロイ用ツール | [AWS Lambda APIを導入する](#aws-lambda-apiを導入する) |

以下のコマンドは、取得したリポジトリのルート（[README.md](../README.md)があるディレクトリ）で実行してください。使いたい機能の手順だけを進めれば構いません。

## ブラウザーで画像を編集する

### 画像を開く

1. [AnnoForge](https://uchimanajet7.github.io/annoforge/)を開きます。
2. 「画像を選択」で画像ファイルを選ぶか、キャンバスへドラッグ&ドロップします。

リポジトリを手元に取得済みなら、[web/index.html](../web/index.html) をブラウザーで直接開く方法も使えます。描画ライブラリのKonva.jsを外部CDNから読み込むため、ローカル利用でもインターネット接続が必要です。

別の画像を読み込むと、現在の画像と注釈が置き換わります。残したい作業は先に保存してください。

### 図形を描く・編集する

図形ツールを選び、画像上で操作します。

| 図形 | 描き方 |
|---|---|
| 矩形 | 対角の2点をドラッグで指定 |
| 直線 | 始点から終点までドラッグ |
| 多角形 | クリックで頂点を追加し、ダブルクリックまたはEnterで確定 |
| 平行四辺形 | 3点を順にクリック。4点目は自動で補完 |
| 円 | 中心から外側へドラッグし、離して確定 |

- 移動・変形: 選択ツールへ切り替え、図形を選択します。本体をドラッグして移動し、表示されるハンドルや頂点をドラッグして形を調整します。
- 重なった図形: キャンバスでは最前面の図形が選ばれます。隠れた図形は「アノテーション一覧」から選択すると、編集できるよう一時的に前面へ表示されます。
- 色: 図形を選択してからパレットやカラーピッカーを操作すると、その図形の輪郭線を変更できます。図形を選択していないときは、次に描く図形の色を設定します。
- 表示: 右下の＋/−/リセットで拡大・縮小できます。選択ツール中は背景のドラッグで表示位置を移動でき、タッチ操作ではピンチズームも使えます。

### PNGとJSONを保存する

1. 完成画像は「注釈付き画像を保存」でPNGとして保存します。元画像と同じ寸法で、表示の拡大・縮小や移動、編集中の選択枠は含みません。
2. 注釈データは「JSON形式」欄の「JSONをダウンロード」で保存します。「JSONをコピー」も利用できます。
3. ブラウザーのダウンロード一覧で保存完了を確認し、保存したファイルを開いて内容を確認してください。

作業状態は自動保存されません。ページを閉じる・再読み込みする・別の画像を開く前に保存してください。JSONには元画像が含まれないため、元画像も保管してください。

注釈を再利用するときは、元画像を開いてから「JSONをインポート」で保存したJSONを読み込みます。貼り付け・ファイル選択・ドラッグ&ドロップに対応し、現在の注釈を置き換えます。矩形・円の回転角はJSONに保存されないため、回転を使った場合の見た目はPNGで保存してください。詳しいデータ形式は[製品仕様](SPEC.md)を参照してください。

## WebMCPでAIエージェントと使う

### 対応環境と基本の流れ

Site toolsに対応したクライアントが必要です。ChatGPT / Codexのモデル・ワークスペースなどの利用条件は、[OpenAIのSite tools案内](https://learn.chatgpt.com/docs/webmcp)で確認してください。通常のブラウザー操作にはWebMCP対応は不要です。

1. 対応クライアントの内蔵ブラウザーで[AnnoForge](https://uchimanajet7.github.io/annoforge/)を開き、Site toolsを利用できることを確認します。
2. 画像を画面から読み込むか、エージェントへ画像URLを渡して読み込みを依頼します。外部URLを使う場合はHTTPSの画像URLと、配信元のCORS許可が必要です。会話に添付した画像を渡せるかどうかはクライアントの機能に依存します。
3. エージェントへ、対象と付けたい注釈を伝え、Site toolsで画像を確認して注釈を反映するよう依頼します。画像認識と注釈候補の生成はエージェントが行います。
4. エージェントの操作が停止してから、同じタブのキャンバスで必要な図形を手動修正します。編集後も同じタブを維持し、ページは再読み込みしません。
5. 修正したことをエージェントへ伝え、最新状態の確認と、修正を保持したPNG・JSONの出力を依頼します。会話で受け取る場合は次の依頼例を使えます。ブラウザーへ保存する場合は、ダウンロード一覧と実ファイルで結果を確認してください。

### PNGとJSONを会話で受け取る

WebMCPでファイルのデータを取得することと、会話へ画像やファイルを提示することは別の処理です。ページを開くだけでは、ファイルの受信・添付処理は自動実行されません。

依頼例:

```text
同じAnnoForgeページで、画面からアノテーションを手動修正しました。
現在の注釈を変更せず、元画像寸法の完成PNGと完全な注釈JSONを取得してください。

WebMCPのprepare_annotation_exportとread_annotation_exportによる直接受信を優先してください。
戻り値はSite toolsを呼ぶのと同じJavaScript実行環境内で復号し、
このタスクで書込みを許可されている出力先へ保存してください。
受信データの保存・読取りと、最終回答への画像・ファイルリンクの提示を許可します。

両ファイルのバイト数・SHA-256・revisionを確認し、PNGを画像として開いて確認してください。
最終回答に完成PNGの画像を表示し、PNGとJSONの実ファイルへのリンクを付けてください。
ツールのプレビューや「保存を開始した」という報告だけでは完了ではありません。

直接受信できない場合だけ、許可範囲内のブラウザー・ファイル機能へ切り替えてください。
保存ボタンの押し直しだけで済ませず、実ファイルを取得できたことを確認してください。
必要な機能や権限がない場合は、未完了の工程と必要なものを報告してください。
```

リポジトリの取得やNode.jsのインストールを利用者が行う必要はありません。エージェントが、対応クライアントにあるSite toolsの実行環境とファイル保存・表示機能を使用します。これらの機能がないクライアントでは、会話へのファイル提示まで実行できるとは限りません。

連携を実装・検証する開発者向けに、[同梱受信モジュールの接続例](WEBMCP.md#411-クライアント側の受信と会話への添付)があります。ツールの成功メッセージだけでなく、会話で画像を確認でき、JSONファイルを開けることを確認します。

直接受信を利用できない場合は、利用者の許可とクライアントの機能に応じてダウンロードなどの代替経路を使います。代替経路での保存確認やツールごとの制約は、[WebMCP仕様](WEBMCP.md)に記載しています。

### 手元のリポジトリをWebMCPで使う場合

手元のリポジトリを対応クライアントから使う場合だけ、ローカル静的サーバーを起動します。macOS / Linux向けの起動スクリプトです。対応するOS・CPUと必要コマンドは[ローカル静的サーバーの対応環境](WEBMCP.md#52-対応環境)を確認してください。

```bash
bash scripts/tools/web/start-local-web.sh
```

初回はStatic Web Serverをダウンロードしてリポジトリ内に配置します。以後の起動時も最新安定版を確認し、更新がある場合は置換するか確認します。

起動後は、対応クライアントの内蔵ブラウザーで `http://127.0.0.1:8000/` を開き、上記と同じ流れで操作します。終了時は、起動したターミナルで `Ctrl+C` を押してください。ポート変更や起動時の確認事項は[開発セットアップ](DEV_SETUP.md#35-webmcpのローカル静的サーバー)を参照してください。

## GitHub Pagesで自分のサイトを公開する

自分のGitHubリポジトリからAnnoForgeを公開する場合の手順です。

1. 自分のGitHubリポジトリにAnnoForgeを用意します。フォークを使う場合は、Actionsタブでワークフローが有効になっていることを確認してください。
2. リポジトリの Settings → Pages → Build and deployment → Source で「GitHub Actions」を選びます。
3. Actions → Pages → Run workflow で `main` ブランチを選び、公開を実行します。以後は `main` へのpushでも公開されます。
4. ワークフローの成功後、Settings → Pages に表示される公開URLを開きます。通常は `https://<owner>.github.io/<repo>/` ですが、実際に表示されるURLを使用してください。

公開処理は[Pagesワークフロー](../.github/workflows/pages.yml)で定義しています。設定の詳細はGitHub公式の[GitHub Pagesのカスタムワークフロー](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)を参照してください。

## AWS Lambda APIを導入する

ブラウザーだけで行う画像編集とは別に、API経由で画像に注釈を描画し、S3に保存する場合の手順です。自分のAWS環境にリソースを作成します。

### 準備

macOS / Linuxで、AWSアカウント・必要権限・AWS認証と、Terraform / AWS CLI v2 / Python 3.13 + pip / curl / jq / zipを用意します。必要バージョンと導入方法は[デプロイ手順の前提](DEPLOY.md#0-前提-ツールとインストール案内)を確認してください。これらは通常のWeb UI利用には不要です。

### デプロイと確認

認証ラッパー経由で、対話形式のデプロイを開始します。

```bash
bash scripts/deploy/with_aws.sh -- bash scripts/deploy/deploy.sh
```

AWSプロファイルを選び、案内に従って設定します。作成されるリソースをTerraformのplanで確認してから適用してください。設定項目や固定プロファイルなどの指定方法は[デプロイ手順](DEPLOY.md)を参照してください。

デプロイ後にAPIの動作を再確認する場合は、次のスモークテストを使います。APIへのPOSTと、返された画像URLへのGETが成功することを確認します。

```bash
bash scripts/deploy/with_aws.sh -- bash scripts/deploy/smoke.sh
```

APIの呼び出し形式は[製品仕様](SPEC.md)、出力値の確認・リソースの削除・トラブルシュートは[デプロイ手順](DEPLOY.md)を参照してください。削除手順はAWSリソースを削除する操作なので、対象と残したいデータを確認してから実行してください。
